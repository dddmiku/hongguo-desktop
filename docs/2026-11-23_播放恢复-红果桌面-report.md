## 3. 为什么以前“修了还复发”

以前的多层逻辑各自管一小段恢复：Lease 的快速重试、HLS 网络恢复、decoder watchdog、暖槽重试和切集接管没有同一所有权/健康口径。局部通过不代表组合路径通过：

1. 几百毫秒的请求重试不足以覆盖秒级故障，失败后又关闭了播放意图。
2. POST 成功或 API ready 不是新画面健康，既不能刷新预算，也不能锁死下一次恢复。
3. 自动接管变更 warm 标志，不应该同时撤销原任务已经拥有的重试资格。
4. currentTime 可以由音轨推进，恢复策略的健康判定必须用真实视频帧，不依赖 UI 布尔标志。
5. 取消必须在“ready 到 commit”之间再核对，且旧任务的 finally 只能清理自己。
6. 没有故障事件链时，每次只能猜；普通环形日志若正常播放覆盖故障，也不能治本。

本轮不是单纯把次数从三改到更多，而是把恢复策略、候选事务、暖接管、真实健康和错误跨 IPC 分类的责任重新对齐。

## 4. 新恢复契约

- 当前中断只有一个恢复 Promise；单次尝试只发一份 POST，没有 Lease 内嵌套重试。
- 退避为 1/2/4/8 秒封顶；累计 60 秒**有效前台在线预算**，暂停、隐藏、离线不增加恢复请求、不计该预算。
- 候选 API ready 但未达到真实视频帧健康时再次出错，仍继续原 incident 和原预算，并退避；连续 ready 不能无限续命。
- 网络/超时及 429/502/503/504 可恢复；401/403、HTTP 200 格式错误、确定的片源/编码业务失败不当成网络错误重试。HTTP 503 非 JSON 是 HTTP 临时故障，而非成功响应协议错误。明确的 wire retryable=false 不能被重新放开。
- Lease 的 read 真正只 GET；需要恢复由协调器接管。候选就绪并复核取消前不成为 current。
- 在途结果取消/预算到期即停止等待；跨 IPC 已发出的响应仍被消费，迟到候选不加载、不串槽并释放。
- 始终两个解码槽。旧 current＋下一暖槽＋私有候选可瞬态三份 lease；稳态最多两份，退出归零。三份 lease 不等于三个解码器。

遇到真正持续不可用或确定的业务失败，仍会给出可读错误和手动重试入口；不是掩盖故障或无限重试。

## 5. 验证口径与原始失败保留

所有故障回归使用实际 Player/HlsDeck/HLS 请求与解码帧。故障通过真实本地 HTTP 404、取源不可用或候选迟到触发，不赋值制造 ended/currentTime 来假装自然播放。test profile 隔离、静音隐藏，不使用真实账号写云端进度。

已完成证据：

- tail404-outage：强场景 5/5 自然到 127，播放超过 2 秒后再连续观察 3.2 秒，时间前进约 9.6 秒并有真实新帧。
- consecutive-outages：前一版本 5/5；最终冻结后 1/1，两次独立故障间有真实视频健康，实际保持 3×；音量/静音偏好由 controls-interrupt 验证。
- controls-interrupt：暂停冻结、不追加 POST；隐藏/恢复保持意图。controls-cancel-late：晚到候选 DELETE 一次，不加载、不串槽，127 继续。
- replacement-before-health：强场景 5/5；坏候选 manifest 404、零 200 媒体响应，同集严格初始＋坏替换＋再次替换三次 POST，自然 127 持续 3× 新帧。
- 真实 Main/preload/IPC：媒体 16 项、诊断 11 项通过；包括 JSON clone、403/503、非 JSON 200/503、malformed、非法 sender 和非法参数零 Supervisor 调用。

- 随包 Python 3.11.9＋原 PyAV/服务库＋已有测试专用依赖环境，352/352 服务测试通过；发布/工具测试 31/31 通过。裸系统 Python 的单项 remux 失败已独立定位为缺 PyAV，正确运行时同项通过，没有修改产品代码或运行时。

## 7. 新诊断如何用于下一次定位

用户数据目录中新增 `playback-diagnostics.jsonl` 和固定 `playback-diagnostics.last-error.jsonl`。普通文件最多 500 条/256KiB、一槽 .bak；最近故障最多 200 条。正常事件队列与最新故障槽独立，正常连播不覆盖故障。IO 失败不能影响播放；拒绝符号链接和多硬链接。

记录闭合枚举和数值/布尔：HTTP status、deck slot、episode、job/lease generation、readyState、实际倍速、媒体/源时长、bufferedEnd、最近视频帧时刻及帧龄、暂停/隐藏/恢复状态、transportPending 等。**不保存任意 message、URL、headers、Cookie、账号、session ID、token、密钥。**

- `occurredAtMs` 是事件发生时刻；`receivedAtMs` 是 Main 收到时刻，不能混用。
- Renderer recorder 自产 traceGeneration/sequence；Main 生成 bootStartedAtMs/contextGeneration 并固定 observer。
- 事件身份为 boot/context/observer/traceGeneration/sequence；不同 observer 的 sequence/jobGeneration 不直接比较。
- 下一次复发可通过设置中的“导出诊断”，合并常规日志与最近故障，按上述身份和发生时间检查取源→替换→新帧→切集，不再仅凭截图猜测。
