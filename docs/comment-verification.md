## 原因与修复

1. 评论请求只签名 URL 和请求头，未将实际正文传给签名服务。同一集、相同正文下，原请求被上游拒绝；仅补正文签名即可返回 `code=0` 和 20 条评论。改用现有账号请求通道，正文压缩、签名及当前登录会话由同一实现处理。
2. 上游分页游标是完整字符串，旧代码将其转换成整数 0。服务、数据契约和界面现完整保留并 URL 编码游标。继续分页缺少有效游标或游标没有前进时返回可重试错误，避免重复首屏。
3. 评论错误使用现有消息清理函数，分页失败保留已显示的评论。缓存按登录会话隔离，账号切换时重新挂载评论组件，旧账号和旧集迟到回复均被丢弃。
