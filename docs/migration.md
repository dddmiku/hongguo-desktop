# 从旧桌面版迁移到新客户端 1.0.0

1.0.0 是独立源码构建的新客户端初代正式版本，具有新的应用 ID、安装目录和数据目录。旧用户可通过旧客户端的更新入口下载新版安装包，并按安装向导安装到新的独立目录；安装完成后，新客户端只读导入旧记录。旧程序和旧数据保留，方便回退。

## 新旧版本序列

旧客户端已到 1.9.9，但新客户端从 1.0.0 起独立迭代。为让旧版更新器正确发现移交下载，旧更新入口发布 **1.9.10 兼容桥**。这个版本号只服务于旧 1.9.9 的更新比较，不能用作新客户端的界面版本、安装包版本或源码发行版本。

通过兼容桥进入后，实际安装的是新客户端 **1.0.0**。新应用使用自己的公开源码仓库和后续更新链路；以后按 SemVer 递增，功能新增使用次版本，修复与兼容优化使用修订版本。只有破坏兼容或重大产品代际变化才提升主版本。

## 可导入的内容

迁移读取 `%APPDATA%\cn.guoban.desktop-companion` 中的两个固定文件：

- `guoban.sqlite3`：观看历史、收藏，以及 `settings` 表中存在的合法播放偏好。
- `desktop-account.json`：有效会话的有限字段，仅交给主进程和受保护的本地服务，用于恢复登录。不会进入界面、日志或诊断文件。

旧观看历史保留剧名、封面、集数和观看时间。已核验的旧表只有 `last_episode`，没有秒级播放进度，因此这类记录从对应集开头继续；迁移不会编造播放秒数。如果旧数据库版本实际具有 `position` / `duration` 列，则导入真实值。

主进程明确提供旧 WebView 数据目录时，迁移还会以只读方式解析其 `Local Storage/leveldb`，仅读取已确认的 `guoban:quality` 与 `guoban:preferences` 两个键，恢复画质、倍速和自动连播。读取使用 LevelDB 的活跃文件清单、记录校验和与 Snappy 解码，不打开浏览器数据库写连接，也不返回其他 localStorage 数据。已在本机真实数据中读出 1080p、3 倍速与开启自动连播；这些值来自原记录，不是按截图为所有用户写死。

未显式提供 WebView 路径、文件损坏或格式不支持时，迁移保留合法 SQLite 偏好或新版默认值，可在设置页重新选择。窗口偏好暂不从 WebView 中导入。旧缓存不迁移，新客户端按自己的空间上限管理缓存。

## 导入与回退

迁移在主进程里完成。主进程保存迁移标记，避免重复导入；导入历史不会写入待同步队列，也不会把旧进度重新推送到云端。恢复登录后仍按新客户端正常的同步规则读取云端数据。

读取旧库使用 SQLite 只读连接和只读事务，兼容正在使用的 WAL 数据库。迁移不删除、移动或修改旧文件，也不会关闭旧程序。旧数据库损坏或被系统拒绝读取时，新客户端提示导入失败并继续保留旧数据；可退出旧客户端后重试。

若需要回退，退出新客户端并打开原来的旧客户端即可。卸载新客户端时保留其数据；旧安装和旧数据不受迁移影响。

## 开发验证

运行 `npm test -- electron/migration.test.ts`。测试在项目 `_work/migration-tests` 下生成合成 SQLite 与会话文件，验证字段映射、WAL 读取、偏好白名单、无损读取和损坏数据库处理。测试不会发送真实短信、登录或向云端写入进度。
